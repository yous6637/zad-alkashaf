# زاد الكشاف

منصة عربية أولاً (مع واجهة فرنسية) لسوق عتاد الأفواج الكشفية في الجزائر. الفوج يسجّل، يطلب اشتراكاً، ينشر منتجات للبيع أو الكراء أو التبادل أو الطلب، والزائر يبحث ويتواصل مع صاحب الإعلان مباشرة. لا يوجد دفع داخل المنصة.

اللغة في المسار: العربية على `/ar` والفرنسية على `/fr`. الجذر `/` يحوّل إلى `/ar`. النصوص في `messages/ar.json` و`messages/fr.json`، والاتجاه من اليمين لليسار في العربية.

## التشغيل

```bash
npm install
npm run dev
```

المعاينة على `http://127.0.0.1:8080`. بلا `DATABASE_URL` تستخدم Postgres مضمّناً (PGLite) وتطبّق `migrations/*.sql` عند الإقلاع، بما فيها بيانات الولايات والتصنيفات والباقة والأفواج والمنتجات التجريبية.

```bash
npm run typecheck
npm run lint
npm run build
```

`npm run build` يشغّل الهجرة على `DATABASE_URL` إن وُجد.

## المتغيرات

| المتغير | الدور |
|---|---|
| `DATABASE_URL` | Postgres حقيقي (Neon أو Supabase). بدونه تعمل PGLite ولا تُنفَّذ هجرة `pg`. |
| `BETTER_AUTH_SECRET` | سر الجلسات في الإنتاج. المعاينة تولّد سراً محلياً. |
| `BETTER_AUTH_URL` | عنوان الموقع العام في الإنتاج. |

لا تُكتب كلمة سر القاعدة في المستودع. ضع `DATABASE_URL` في بيئة التشغيل فقط. اتصال Supabase يستخدم SSL دون التحقق من سلسلة الشهادة، لأن المضيف الوسيط يقدّم شهادة لا يثق بها Node افتراضياً. المضيف المباشر `db.<ref>.supabase.co` قد لا يُحلّ من بعض الشبكات؛ مجمّع الجلسة (session pooler) على المنفذ `5432` والمستخدم `postgres.<project-ref>` هو البديل.

حدود السعر والمدة والأعضاء والمنتجات لا تُثبَّت في الواجهة. تُقرأ من `plans` وتُنسخ إلى الاشتراك عند الطلب.

## المسارات

كل المسارات التالية تحت `/$locale` حيث `locale` هو `ar` أو `fr`. قيمة أخرى تُحوَّل إلى `ar`.

| المسار | من يصل | ماذا يفعل |
|---|---|---|
| `/` | الجميع | تحويل إلى `/ar`. |
| `/$locale` | الجميع | الرئيسية: بحث، تصنيفات، أفواج، ومنتجات ظاهرة. |
| `/$locale/products` | الجميع | كتالوج مع بحث ونص، تصنيف، ولاية، نوع العرض، الحالة، وسقف السعر. السعر يصفّي البيع والكراء فقط. |
| `/$locale/products/$id` | الجميع | صفحة منتج ظاهر: الصورة، السعر، الولاية، الفوج، الوصف، منتجات أخرى من نفس الفوج. التواصل والبلاغ يتطلبان دخولاً. |
| `/$locale/troops` | الجميع | قائمة الأفواج النشطة. |
| `/$locale/troops/$id` | الجميع | صفحة فوج نشط ومنتجاته المتاحة. الفوج الموقوف أو قيد المراجعة لا يُعرض للعامة. |
| `/$locale/register` | زائر | إنشاء حساب بالبريد وكلمة المرور. |
| `/$locale/login` | زائر | دخول. بعد الدخول يختار المستخدم إنشاء فوج أو طلب الانضمام. |
| `/$locale/account` | مسجّل | إن لم يرتبط بفوج: إنشاء فوج أو طلب انضمام. إن كان مديراً: العتاد، الأعضاء وطلبات الانضمام، الاشتراك، وبيانات الفوج. العضو يرى فوجه دون إدارة. |
| `/$locale/account/product` | مدير فوج | نموذج نشر منتج أو تعديله. غيره يُعاد إلى الحساب. |
| `/$locale/admin` | `profiles.role = admin` | لوحة المنصة: أفواج، اشتراكات، منتجات، بلاغات، والباقة. غير المدير يُعاد إلى الرئيسية. |
| `/api/auth/$` | Better Auth | `GET` و`POST` لكل مسارات الجلسة (`/api/auth/sign-in/email` وغيرها). لا توجد واجهة REST أخرى للمنتجات. |

## دوال الخادم

المنطق ليس REST عاماً. الصفحات تستدعي دوال `createServerFn` في `src/lib/zad/api.ts`. كل مدخل يُتحقق منه بـ Zod. الدوال التي تغيّر بيانات تمر على `authMiddleware` وتقرأ المستخدم من الجلسة، لا من معرّف يرسله المتصفح.

الظهور العام للمنتج يعني معاً: `visibility = public` و`status = active` وفوج `active` واشتراك سارٍ (`has_active_subscription`).

### قراءة عامة

| الدالة | المدخل | الناتج |
|---|---|---|
| `getMeta` | `locale?` | التصنيفات النشطة، الولايات (1–58)، والباقة النشطة الأرخص. |
| `listProducts` | `q?` `categoryId?` `wilayaCode?` `operation?` `condition?` `maxPrice?` `limit?` (حتى 48) `locale?` | إعلانات ظاهرة تطابق التصفية، الأحدث أولاً. |
| `getProduct` | `id` `locale?` | المنتج إن كان ظاهراً، مع شعار الفوج والبلدية، وحتى 4 منتجات أخرى من نفس الفوج. وإلا `null`. |
| `listTroops` | `locale?` | الأفواج ذات الحالة `active`، مع عدد المنتجات الظاهرة والأعضاء والشعار. |
| `getTroop` | `id` `locale?` | فوج نشط ومنتجاته الظاهرة. غير النشط يُعامل كغير موجود. |

### الحساب والفوج

| الدالة | من | ماذا تفعل |
|---|---|---|
| `getMe` | مسجّل | الاسم، البريد، دور المنصة، الفوج، الاشتراك الأقرب (نشط ثم قيد المراجعة)، العدادات، وطلب الانضمام المعلّق إن وُجد. |
| `getCurrentUser` | مسجّل | ملخص أقصر للحراسة: المعرّف والاسم والدور و`troopId`. |
| `ensureMyProfile` | مسجّل | ينشئ صف `profiles` إن غاب، ويحدّث الاسم الظاهر. |
| `registerTroop` | مسجّل بلا فوج | ينشئ فوجاً بحالة `pending`، ويربط المنشئ بدور `troop_manager`. يلغي أي طلب انضمام معلّق له. |
| `updateTroop` | مدير الفوج | يعدّل الاسم والولاية والبلدية والوصف والهاتف والبريد والشعار والغلاف. لا يغيّر `status`. |
| `joinTroop` | مسجّل بلا فوج | ينشئ `join_requests` بحالة `pending` لفوج `active`. لا يربطه عضواً. طلب واحد معلّق فقط. |
| `cancelJoinRequest` | صاحب الطلب | يعلّم طلبه المعلّق `rejected`. |
| `listJoinRequests` | مدير الفوج | طلبات `pending` لفوجه: الاسم والبريد. |
| `decideJoinRequest` | مدير الفوج | `accept: false` يرفض. `accept: true` يربط الحساب `member` إذا كان الاشتراك سارياً والفوج نشطاً ولم يبلغ حد الأعضاء. |
| `requestSubscription` | مدير الفوج | طلب اشتراك `pending` ينسخ السعر وحدود الباقة النشطة، مع ملاحظة الدفع. طلب معلّق واحد لكل فوج. |
| `claimAdmin` | مسجّل | يجعله `admin` فقط إذا لم يوجد أي مسؤول بعد. |

### العتاد والأعضاء

| الدالة | من | ماذا تفعل |
|---|---|---|
| `saveProduct` | مدير الفوج وباشتراك سارٍ | ينشئ منتجاً أو يعدّل منتج فوجه. البيع يطلب سعراً، والكراء سعر كراء، والتبادل والطلب بلا سعر. المحفّز يرفض تجاوز `max_products`. |
| `setProductStatus` | مدير الفوج | يبدّل `active` و`unavailable`. |
| `deleteProduct` | مدير الفوج | يحذف منتج فوجه. |
| `listOwnProducts` | عضو الفوج | منتجات فوجه بما فيها غير الظاهرة، للوحة الحساب. الكتابة للمدير فقط. |
| `addMember` | مدير الفوج وباشتراك سارٍ | يربط حساباً موجوداً عبر البريد بدور `member` إن لم يكن في فوج. حد الأعضاء من الاشتراك. |
| `removeMember` | مدير الفوج | يفصل عضواً (`troop_id` فارغ). لا يفصل المدير نفسه. |
| `listMembers` | عضو الفوج | أعضاء فوجه النشطون. |

### التواصل والبلاغات

| الدالة | من | ماذا تفعل |
|---|---|---|
| `getListingContact` | مسجّل مرتبط بفوج | هاتف وبريد الفوج صاحب إعلان ظاهر. بلا فوج: `need_troop`. إعلان غير ظاهر: `gone`. |
| `sendReport` | مسجّل | بلاغ على إعلان ظاهر. لا يبلّغ عن إعلان فوجه. سبب واحد من `wrong_info` `inappropriate` `duplicate` `other`، وتفاصيل حتى 400 حرفاً. مرة واحدة لكل زوج (منتج، مبلّغ). |
| `listInbox` | مسجّل | ترجع قائمة فارغة. لا صندوق رسائل؛ التواصل بالهاتف والبريد. |
| `markNotificationsRead` | مسجّل | لا تكتب شيئاً. الإشعارات غير مخزّنة في هذه النسخة. |

### الإدارة

كلها تشترط `profiles.role = admin`.

| الدالة | ماذا تفعل |
|---|---|
| `adminOverview` | الأفواج (مع اشتراك معلّق إن وُجد)، الاشتراكات، المنتجات، البلاغات، والباقة النشطة. |
| `adminSetTroopStatus` | `pending` أو `active` أو `suspended`. |
| `adminActivateSubscription` | ينهي الاشتراك النشط السابق، ويفعّل الطلب من الآن لمدة `duration_days` في الباقة، ويجعل الفوج `active`. |
| `adminHideProduct` | `hidden: true` يخفي الإعلان (`visibility = hidden`). `false` يعيده `public`. |
| `adminResolveReport` | يعلّم بلاغاً مفتوحاً `resolved` ويسجّل المعالج والوقت. |
| `adminUpdatePlan` | يعدّل سعر الباقة النشطة ومدتها وحد الأعضاء وحد المنتجات. يسري على الطلبات التالية فقط. |

## المخطط

المصدر هو `migrations/` بالترتيب الأبجدي للاسم، ويُسجَّل في `_migrations`. المجلد `migrations/auth/` لا يُطبَّق وحده؛ النسخة المعتمدة للمصادقة هي `migrations/0001_auth.sql`.

`0002_zad.sql` مخطط قديم. `0003_spec.sql` يسقط جداول التطبيق ويعيد إنشاء المخطط المعتمد. ما يلي يعدّل ذلك المخطط.

الاتصال الحالي بصلاحية مالك القاعدة ويتجاوز RLS. السياسات مكتوبة مع ذلك. حدود الأعضاء والمنتجات تُفرض بمحفّزات وتعمل حتى مع المالك.

### المصادقة (`0001_auth.sql`)

جداول Better Auth: `"user"` و`"session"` و`"account"` و`"verification"`. `profiles.id` يساوي `"user".id` وهو نص وليس UUID.

### الأنواع

| النوع | القيم |
|---|---|
| `user_role` | `admin` `troop_manager` `member` |
| `troop_status` | `pending` `active` `suspended` |
| `subscription_status` | `pending` `active` `expired` `suspended` |
| `listing_type` | `sale` `rent` `exchange` `wanted` |
| `item_condition` | `new` `used_good` `needs_repair` |
| `product_visibility` | `public` `troops_only` `hidden` |
| `product_status` | `active` `unavailable` |
| `report_reason` | `wrong_info` `inappropriate` `duplicate` `other` |
| `report_status` | `open` `resolved` `dismissed` |
| `join_request_status` | `pending` `accepted` `rejected` |

### الجداول

| الجدول | أهم الأعمدة | قواعد |
|---|---|---|
| `wilayas` | `id` 1–58، `name_ar`، `name_fr` | قراءة عامة. التطبيق لا يكتبها. |
| `plans` | `price_dzd`، `duration_days`، `max_members`، `max_products`، `is_active` | الصف النشط يُقرأ للتسجيل. الكتابة للإدارة. |
| `troops` | الاسم، الولاية، البلدية، الوصف، الهاتف، البريد، `status`، `logo_path`، `thumbnail_path` | الزائر يرى `active`. المدير يعدّل فوجه ولا يغيّر الحالة. الإدارة تعدّل الكل. الشعار والغلاف نص JPEG بعد تصغير في المتصفح، بلا مخزن ملفات. |
| `profiles` | `id`، `troop_id`، `full_name`، `phone`، `role`، `is_active` | مدير واحد لكل فوج (فهرس فريد جزئي). المستخدم لا يغيّر دوره ولا فوجه بنفسه. |
| `subscriptions` | الفوج، الباقة، السعر والحدود المنسوخة، `starts_at`، `ends_at`، `status`، `payment_note` | طلب `pending` واحد واشتراك `active` واحد لكل فوج. المدير ينشئ `pending` فقط. الإدارة تغيّر الحالة والتواريخ. |
| `categories` | `slug`، `name_ar`، `name_fr`، `parent_id`، `sort_order`، `is_active` | النشطة للجميع. |
| `products` | الفوج، المنشئ، التصنيف، العنوان، الوصف، النوع، الحالة، السعر أو سعر الكراء، الولاية، `visibility`، `status`، `published_at` | البيع يطلب `price_dzd` فقط. الكراء يطلب `rent_price_dzd` فقط. التبادل والطلب بلا سعر. |
| `product_images` | `product_id`، `storage_path`، `sort_order` | نفس ظهور المنتج الأب. المسار نص؛ رفع الملفات غير موصول بالواجهة. |
| `reports` | المنتج، المبلّغ، السبب، التفاصيل، الحالة، المعالج | قراءة وتحديث للإدارة. إدراج للمبلّغ عن نفسه. فريد `(product_id, reporter_id)`. |
| `join_requests` | الفوج، المستخدم، الحالة، `handled_by`، `handled_at` | طلب `pending` واحد لكل مستخدم. القبول يحدّث `profiles` ولا يتم في الواجهة وحدها. |

### دوال وقيود في القاعدة

- `has_active_subscription(troop)` صحيحة إذا الحالة `active` و`ends_at` بعد الآن.
- قبل إدراج منتج: `NO_ACTIVE_SUBSCRIPTION` أو `LIMIT_PRODUCTS`. العدّ يشمل كل منتجات الفوج، بما فيها المخفية.
- قبل ربط عضو (`troop_id` على `profiles`): `NO_ACTIVE_SUBSCRIPTION` أو `LIMIT_MEMBERS`، إلا أول ربط وهو مدير التأسيس. العدّ على `is_active`.
- مدة الاشتراك تُحسب عند الموافقة: `ends_at = now() + duration_days` من الباقة. المدة غير منسوخة في صف الاشتراك. تعديل الباقة لا يغيّر اشتراكاً قائماً.
- انتهاء الاشتراك يُفحص عند القراءة. لا توجد مهمة مجدولة تخفي المنتجات.

البذرة في `seed.sql` تضع 58 ولاية وتصنيفات وباقة (2000 دج، 365 يوماً، 10 أعضاء، 30 منتجاً). `troops.sql` و`z-products.sql` بيانات تجريبية. هذه أرقام بذرة وليست ثوابت في الواجهة.

## أول مسؤول

لا يُزرع حساب بكلمة مرور.

1. سجّل من `/ar/register`.
2. إن لم يوجد مسؤول، صفحة الحساب تعرض تفعيل الإدارة لأول حساب (`claimAdmin`).
3. أو بعد معرفة المعرّف في `"user"`:

```sql
update profiles set role = 'admin' where id = '<user id>';
```

## النشر

اربط المستودع بخدمة Node واضبط `DATABASE_URL`. `npm run build` يطبّق الملفات التي ليست في `_migrations`. الواجهة العربية من `/`، والفرنسية من `/fr`.

تفاصيل السياسات الأقدم في [docs/SCHEMA.md](docs/SCHEMA.md). هذا الملف هو شرح المسارات والدوال والمخطط كما هي في الكود الآن.
